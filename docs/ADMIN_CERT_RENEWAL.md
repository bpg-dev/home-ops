# Admin Certificate Renewal (kubeconfig / talosconfig)

Both admin credentials in this repo carry one-year client certificates.
Nothing renews them automatically.

| Credential | Generated by | Valid until | Alert |
| --- | --- | --- | --- |
| `./kubeconfig` (CN=admin) | `talosctl kubeconfig` | 2027-10-27 | yes |
| `talos/clusterconfig/talosconfig` | talhelper | 2027-10-04 | none |

`KubeClientCertificateExpiration` warns 7 days and pages 24 hours before the
kubeconfig certificate expires. The talosconfig has no alert; check
`talosctl config info` when renewing the kubeconfig.

## How the alert looked (2026-10-27)

`KubeClientCertificateExpiration` fired for a single apiserver instance
(`192.168.1.12:6443`). The control-plane VIP lives on one node at a time and
every local `kubectl` call goes to the VIP, so the near-expiry client shows up
on that node only. Talos-managed control-plane certificates (scheduler,
controller-manager, apiserver client certs under `/system/secrets/kubernetes`)
are re-issued on every upgrade/reboot and were fine.

Find the offender:

```bash
# which apiserver sees <7-day certs, and how often
curl -s https://prometheus.${SECRET_DOMAIN}/api/v1/query --data-urlencode \
  'query=sum by (instance) (increase(apiserver_client_certificate_expiration_seconds_bucket{le="604800",job="apiserver"}[1h]))'
# local kubeconfig cert expiry
kubectl --kubeconfig=./kubeconfig config view --raw \
  -o jsonpath='{.users[0].user.client-certificate-data}' | base64 -d \
  | openssl x509 -noout -enddate -subject
# talosconfig
TALOSCONFIG=$PWD/talos/clusterconfig/talosconfig talosctl config info
```

## Renew

```bash
cp ./kubeconfig /tmp/kubeconfig.bak
TALOSCONFIG=$PWD/talos/clusterconfig/talosconfig \
  talosctl -n 192.168.1.11 kubeconfig --force ./kubeconfig
KUBECONFIG=./kubeconfig kubectl get nodes
```

`kubeconfig` is gitignored; copy the new file to every other machine or tool
that used the old one. The alert resolves within ~5 minutes once no client
presents the old certificate; if the `le="604800"` bucket keeps counting,
another copy is still in use.

For `talosconfig`, regenerate with `task talos:generate-config` (talhelper
issues a fresh admin certificate from `talsecret.sops.yaml`).
